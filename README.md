# Summer Linear Attention (SLA)

**Author: summer** · MIT License · research reference / unreviewed prototype

Summer Linear Attention (SLA) combines a **delta-rule fast-weight state** with a **bounded external archive of original key/value pairs**, and uses **null-aware softmax retrieval** to mix archived values with the state prediction. It is designed to investigate how external memory can complement [Summer Delta Attention (SDA)](https://github.com/Summer110622/SummerDeltaAttention). This repository is an educational NumPy reference, **not a trained LLM, optimized GPU kernel, or established improvement over KDA/GDN/Full Attention**.

## Algorithm

With normalized keys `k` and queries `q`, a state `S` of shape `(d_key, d_value)`, and a FIFO archive holding at most `B` original KV pairs:

```text
Sbar    = alpha * S
error   = v - Sbar.T @ k
S       = Sbar + beta * outer(k, error)
logits  = [null_logit, scale * (archived_keys @ q)]
weights = softmax(logits)
fast    = S.T @ q
out     = weights[0] * fast + sum_i weights[i+1] * archived_value[i]
```

The **null candidate** allows the readout to give weight to the fast state instead of forcing a choice among archived values. Its softmax weight is **not** a calibrated probability that the answer is missing. The code uses exact scanning; similar archived keys with contradictory values can be mixed, even if the correct key is the top-1 match.

### Experimental shared-state SDA/SLA readout

The reference implementation exposes `residual_weight` (`lambda` in the expression below):

```text
out_hybrid = out + lambda * sum_i weights[i+1] * (S.T @ (q - archived_key[i]))
```

Here `lambda=0` is the SLA readout. Positive values add **soft SDA-style residual correction** using the *same* state and archive. This is **not equivalent to SDA's hard, confidence-gated top-1 recall**, and does not guarantee exact reproduction of an archived value. Adaptive `lambda`, archive-acceptance gates and learned selection are future research topics, not features of this prototype.

## Quick start

```bash
python -m pip install -e .
python -m examples.quickstart
python -m unittest discover -s tests -v
```

Python >=3.10 and NumPy >=1.24 are required. The [reference module](summer_linear_attention/reference.py) exposes `SLAMemory`.

```python
from summer_linear_attention import SLAMemory

memory = SLAMemory(key_dim=3, value_dim=2, capacity=2, beta=0.05)
memory.write([1, 0, 0], [2, 3], key_id=1)
memory.write([0, 1, 0], [4, 5], key_id=2)
print(memory.read([1, 0, 0]))                       # soft null-aware readout
print(memory.read([1, 0, 0], residual_weight=0.5))  # experimental hybrid
```

For a repeated `key_id` still in the archive, the latest value overwrites that entry. Distinct IDs can share the same normalized key. The default eviction policy is **FIFO**; utility-based selection is not part of the current public reference.

## Experiment figures

The companion SDA repository includes [synthetic recall figures](https://github.com/Summer110622/SummerDeltaAttention#experiment-figures). **This SLA repository does not yet include committed figure-generation scripts, raw benchmark CSVs or audited plots.** Its README therefore does not present earlier exploratory charts as locally reproducible experiments.

The following results are context from earlier exploratory SLA evaluations, **not results generated by the example or test suite in this PR**. See [research status](docs/research_status.md) for their limitations.

### Readout evaluation: SLA vs SDA vs same-budget KV

Earlier synthetic studies tested independent random KV and structured values containing exceptions, under noisy queries. A separate 32-seed replication reported that null-aware SLA readout improved MSE over a calibrated SDA reference and a same-budget null-KV baseline in a *structured-value, noisy-query* condition. This is a **conditional result**: independent random values and stronger out-of-distribution noise did not show uniform improvement.

### Memory policy / accuracy trade-off

A later exploratory comparison found that utility-ranked external memory improved an average across several synthetic access patterns, but **regressed severely on recent-item recall** compared with FIFO. Consequently, the reference keeps FIFO as the default, rather than presenting utility eviction as a proven general solution.

### Similarity collisions and hybrid sensitivity

Adversarial near-duplicate keys with opposing values showed that soft retrieval can blur an otherwise exactly retrievable value. A fixed 50:50 SDA/SLA mixture also failed to outperform both standalone methods consistently. An adaptive readout and a recent-protected archive remain **hypotheses to test**.

## Synthetic evaluation status (not a language-model benchmark)

| Comparison | Current evidence | Caveat |
| --- | --- | --- |
| SLA null-aware readout vs calibrated SDA | Improvement reported in some structured, noisy synthetic conditions | Not uniform over tasks or noise |
| SLA vs same-budget null-KV | Improvement in the same restricted synthetic setting | Not a general same-budget dominance result |
| Utility archive vs FIFO/reservoir/reuse | Better reported macro-average across several synthetic access patterns | **Large failure on recent-item recall** |
| Soft SLA vs hard top-1 retrieval | Soft mixture handles multiple candidates | Can blur near-duplicate contradictory values |
| Fixed SDA/SLA combination | Some cases improve over one component | Not consistently better than both |
| SLA vs trained KDA, GDN or Full Attention | **Not measured** | No trained-model or GPU comparison |

These findings should not be treated as a ranking of full attention architectures. In particular, **the shipped code implements FIFO, not the previously evaluated utility eviction**.

## Memory, time and reproducibility

For `d_key=d_k`, `d_value=d_v`, and fixed archive capacity `B`:

| Component | Stored scalar count / operation |
| --- | --- |
| Delta state | `O(d_k*d_v)` storage and update |
| Original KV archive | `O(B*(d_k+d_v))` storage |
| Exact archive read | `O(B*d_k + B*d_v + d_k*d_v)` work |
| FIFO write | State update plus possible `O(B*(d_k+d_v))` shift and identity lookup |

With **fixed B and dimensions**, processing `N` tokens costs linear work in `N`; if `B` grows in proportion to `N`, an exact full scan per query can yield quadratic total work. The `allocated_array_bytes` property counts only the preallocated NumPy state/key/value arrays; it excludes Python metadata, temporary allocations and runtime overhead.


## How to read the results (adversarial review)

- **A good macro-average is not enough.** A policy that forgets recently useful keys may be unsuitable even if it helps high-loss exceptions.
- **Soft selection is not exact recall.** A correct top-1 candidate can be mixed with an incorrect near-neighbor; the null weight cannot by itself certify correctness.
- **Memory fairness matters.** Account for the state, archived keys/values, metadata and controllers, then allow an archive-only comparator to spend the same budget.
- **SDA is a companion, not an automatically superior hybrid.** Adding soft residual correction with `residual_weight > 0` can improve or worsen error depending on the query distribution.
- **Task mismatch remains.** Synthetic reconstruction does not establish downstream language-model accuracy, trained KDA/GDN superiority, or a GPU speedup.
